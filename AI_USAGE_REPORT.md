**AI OUTPUT THAT WAS WRONG:**
Not in the application code itself (7/7 automated tests passed on the first
run, and manual testing of both a solvable and a deliberately impossible
scenario matched expectations). The one real failure was operational: the
first two attempts to run the FastAPI server for manual testing in the
sandboxed dev environment failed intermittently — the background server
process was silently killed between commands, so follow-up requests got
"connection refused."

**HOW I IDENTIFIED THE PROBLEM:**
`curl` returned "Failed to connect to host" / exit code 7 immediately (not a
timeout), and `ps aux` showed the `uvicorn` process was no longer running
even though it had logged a clean startup a moment earlier — pointing to the
process being torn down with its parent shell rather than a crash in the app.

**HOW I FIXED IT:**
Started the server with `setsid` (`setsid python -m uvicorn ... < /dev/null > log 2>&1 &`)
to fully detach it into its own session so it survives after the invoking
shell exits. Confirmed the fix by checking `ps aux` and hitting the API from
a separate, later command — the server stayed up and every endpoint
(seed, generate on both scenarios, validate, timetable view, CSV export,
drag-and-drop move with both an accepted and a rejected/conflicting move,
and a settings validation edge case) responded correctly.
